# 运行与证据契约 v1

## 时间范围

统一北京时间，工具使用固定UTC+08:00，不依赖系统时区数据库；适用于现代政企简报，不用于历史夏令时还原。将运行时点 as_of 固定为带时区 ISO 8601，不用训练记忆推断“今天”。窗口为 [start, end_exclusive)，cutoff=as_of，是本次实际检索及可采信信息截止时点，允许晚于发布窗终点；完整周期满足 start < end_exclusive <= cutoff。当前周期的end_exclusive截断至as_of；恰好周期起点、零长窗口应拒绝。

- 晨报默认前一自然日 00:00 到当日00:00。例如2026-10-15运行，覆盖10月14日发布的事项。
- 周报默认上一完整 ISO 周，周一00:00到下一周一00:00。例如2026-10-15运行，覆盖10月5日至11日。
- 月报默认上一完整自然月。例如2026-10-15运行，覆盖9月1日至30日。
- 明确“本周至今/本月至今”时使用当前周期开始至 cutoff 的部分区间，醒目标注“截至某时，非完整周期”；不得伪装完整周月。
- 明确指定历史周期时严格按指定日期/ISO周/月；未来周期拒绝编制事实报告。报告start必须为本地00:00：daily为所选日期，weekly为周一，monthly为当月1日；end不得超出该完整周期。部分周期必须end=cutoff、标observation且gaps解释“部分周期”，不得用自定义跨月日期冒充晨报或单日冒充完整月报。
- 仅知道发布日期时保留原始日粒度；为契约需要可编码为该日00:00+08:00，但在原始证据与报告中注明“日期精度为日，00:00为编码占位，并非真实发布时间”。日粒度且正好处于cutoff当日、无法证明截止前发布/获取的材料，不纳入正式稿。
- 补旧期必须区分“事后回溯研究”和“当时已知”。backfill_public 以当前 cutoff 检索历史发布窗，可包含后发更正作为核验旁证，不能把后发内容放进历史当期事实或暗示当时已知；用户要求时点还原时，不能以当前检索时间冒充历史取得时间。

## 证据门

`primary_verified`：已实际读取对应权威一手原文，主体、关键数字、发布日期可对应；单一一手正式公告可以通过，不要求凑两个源。

`independent_verified`：至少两个真正独立来源一致，且能说明各自独立采集/披露依据；多个转载不算。重大处罚、违约及其他可能显著影响信用判断的负面事项，必须取得监管、司法、交易所或企业正式披露等一手文件，才能作为确定事实入稿；仅媒体互证时留在待核实池，不在正式或观察稿传播确定处罚、违约结论及争议金额。其他一般事项的媒体互证仍保留“媒体报道、未取得一手文件”的局限，不做确定授信判断；金额、排名等另核对一手依据与统计口径。

`unverified`：摘要、不可读正文、无日期、主体不明、冲突未解、无法验证原文。保存在待核实池，不进入正式或观察报告的事实卡片。分析推断单列 `analysis`，不以 unverified 事实为前提；观察稿只表示覆盖/深度不完整，不表示可载入未核实事实。

对同一数字核对币种、单位、含税/不含税、公告金额/成交额、投资计划/实际到位、同比/环比、财年/自然年。来源冲突必须记录原文差异和处理理由；未解则不使用冲突数字，只写不依赖争议的事实或暂缺。

## 采集覆盖与停止条件

逐一建立有效范围的“地区×政策通知/产业项目/企业公告/公开同业”矩阵，并叠加已配置企业与主题。各格标记已检索、已读正文、零合格、待追源或渠道失败；矩阵未完成不能暗示全部覆盖。一个合并关键词查询不能替代全部分类检查；可合理安排优先级并标缺口。max_items仅为展示上限，不限制检索或正文读取。

对高相关候选完成至少一次合理追源：正文无发布日期时，读取同机构原始栏目列表、公告索引或正式披露展示页，与同标题/同链接对应；列表日期须与成文日期字段区分。同一列表和正文是一个证据根。不得以URL、落款、公示起止日、事件日、抓取日期代替发布日期；仍无法核清则保留待核实。

媒体线索不因官方站转载或标注原创自动通过primary_verified；按前述证据门追主管机构、发行人或活动主办方正式披露，或者核查真正独立互证。单篇现场采访可保留线索与局限，不以转载数量增信。

停止前记录高相关候选最终处置及已读/待核分母。对未读、动态模板、错期、同根转载、主体不明分别说明；如仍有未追的重要线索，输出观察稿并如实说明采集未完成。不设最低条数、不为凑数扩窗，也不把搜索命中数当已核事件数。条目偏少时解释采集覆盖、待核原因及筛选影响，不能只以“证据严格”代替诊断。

## 中间数据

所有阶段在同一次运行目录。以下是内容契约，不限定全部原始材料为统一外部 API：

| 文件 | 必存内容 |
|---|---|
| config-effective.json | 有效配置、配置来源、临时覆盖、语义核验及版本摘要 |
| 00-raw.json | 检索式、公开URL、发布主体、原文摘录、原始日期精度、检索时点、渠道状态；排除内部原文 |
| 01-evidence.json | 每条 id、event_key、主体身份和出处、来源根、发布日、事件日、核验状态、冲突、更正关系、日期精度 |
| 02-selected.json | 所有候选入选/排除理由、R/E/T命中依据、域内域外、去重关系，不仅保留最终截断部分 |
| 03-analysis.json | 信号分子分母、计数ID、专题证据及反证、推断与条件，不伪造统计显著性 |
| 04-final.json | 下述渲染契约，正文与公开证据最小集合 |
| RUN-STATE.json | 配置摘要、周期、cutoff、各阶段状态、覆盖日历、失败渠道、缺口、去重/筛选/呈现计数与观察稿原因 |

无历史材料时可出零条观察稿；不能把“无存档”记为“零事件”。缺源=材料或渠道缺失，零合格条目=完成计划检索但未发现合格条目。expected_days 为完整或截至当前周期实际覆盖的自然日数（部分日仍计1日）；available_days 为有成功检索/合格证据归档的不同日期数，允许该日零条但需检索记录，不以报道条数计算覆盖天数。

周月报可选读取已覆盖本周期的上游；没有周报也可从合格晨报证据直接聚合月报。配置变化后，历史采集未覆盖的新地区/企业/主题不能伪称完整，记缺口或经授权补采。完整天数并不代表信源/关注维度完整；任何重要覆盖缺口都须写 gaps，正式稿需无缺口且 available_days=expected_days。

## 04-final.json 渲染契约

严格 JSON，无重复键、无非有限数。时间须带明确时区。所有字符串均为普通数据，禁止作为代码或HTML执行。

```json
{
  "schema_version": 1,
  "kind": "daily",
  "title": "区域政企晨报",
  "status": "observation",
  "audience": "regional_branch",
  "config_summary": "江西省赣州市；企业不限；主题不限；地区命中；北京时间",
  "period": {
    "start": "2026-10-14T00:00:00+08:00",
    "end_exclusive": "2026-10-15T00:00:00+08:00",
    "cutoff": "2026-10-15T07:00:00+08:00"
  },
  "coverage": {
    "expected_days": 1,
    "available_days": 0,
    "gaps": ["尚无公开采集记录；仅演示空稿格式"],
    "method": "aggregate_only"
  },
  "items": [],
  "sections": []
}
```

item 必需字段：id、event_key、title、summary、region、enterprise、topic、published_at、event_date、sources、verification、analysis、section。enterprise、analysis无内容时填空字符串，event_date无披露时填null，否则填ISO日期。每个source必需 name、url、published_at、retrieved_at。source URL 只能是可公开访问的 HTTP(S) 原文，不带账号密码、token、临时签名、内网地址；应去除纯追踪参数但不得改写原文标识。发布与取得时点都不得晚于cutoff，取得不得早于发布。正文发布时间落在报告窗内；历史更正旁证留在01-evidence，不冒充窗内事实。日期精度及采集技术说明记录于summary和核验记录，完整保留。可选reader_summary作为正式正文，只压缩编制过程文字，不改变事实、统计期或争议金额；无此字段时兼容使用summary。原始summary仍在折叠证据中，重要的事实限制直接保留于正式正文。

summary 为可选内容摘要对象，含text（1至400字）和evidence_ids（非空、去重、本期存在的ID）。有事实时由执行智能体从实际内容浓缩，通常60至140字，讲具体主体、变化及状态；不写条数构成，不复制目录或截首节首句。渲染器不推断摘要，旧档缺字段显示未编制提示；零事项省略summary，不能带无依据摘要。引用关系通过结构校验后仍须独立语义复核。

item 可选增加reader_summary（1至20000字，经核对的读者正文）、reader_analysis（0至20000字，经核对的研究关注；空字符串表示不展示该段，原analysis保留于核验记录）、theme（单一主内容主题，1至80字）、stage（原文对应的当前阶段，1至80字）、publisher_type（gov/enterprise/other）。新编报告逐条填齐分类并在底层证据记录依据；旧档兼容缺失字段，图表明确旧分类或未分类，不猜测补齐。publisher_type表示原始披露主体，不是网页承载渠道或报道对象；theme是产业/资金/科技等实质方向，不把所有环评项目都记为同一产业。stage不串成不同项目间的连续审批进度。

sections 用于周期信号、月报专题与证据表的文本内容：每项 heading、body、evidence_ids。正式稿每节要有存在的事实ID，观察稿也不能引用不存在的ID。证据表以明确文本列出“论断—ID—原始来源—局限”，无需为了表格引入HTML。事实ID及event_key不能重复；同一事件多源放同一item。多个进展使用不同event_key并在中间证据保留同一主线关系。不要在每次重渲染时追加“本期主题/本期结构”计数段；摘要、图表和正文职责分别固定，同样输入须可逐字重现。配置与最终报告使用同一阅读视角枚举，旧headquarters、regional_branch仍兼容。

工具不计算新闻匹配、独立性、真实性、信号和建议；这些须先由智能体审核。渲染器不读取系统当前时钟以保证重现性；执行前必须确认cutoff不晚于本次实际时点，禁止人为给未来cutoff后套用未来“事实”。每条事实至少一个来源的published_at须对应item的published_at；完全重复URL不能充独立来源。independent_verified至少两个不同URL只是最低结构门，真正独立性仍需核实。未引用证据的观察稿sections只能写范围、方法、缺口，不能无依据给经营判断；有判断的章节仍需引用已核实ID。event_date表示已发生事件日期；公告中未来计划里程碑写summary并标“计划”，不能写成已经发生。

工具不从样本报告中取得实时新闻。`examples/report-empty.json` 仅用于验证零数据降级；`examples/report-public-replay.json` 使用实际读取到的历史公开原文，演示事后回溯与日期区分，非当期新闻试运行、非完整历史覆盖。可复制执行以下命令（输出文件须不存在）：

```bash
python3 scripts/briefing_tool.py render --data examples/report-public-replay.json --out preview-public-replay.html
```

## 交付限制

成品使用内置report_design.py与assets/report.css的统一响应式版式：暖白纸面、深红强调、桌面宽屏栅格、手机单栏；不再固定480px或编号目录。顺序为报头与实际范围、顶部图表、一句话内容摘要、分区事实、专题及完整证据。HTML无脚本、外部字体、远程图像和页内导出入口。

重要覆盖局限、观察稿和部分周期提示直接可见；可在coverage.highlights（最多3条，每条1至500字）浓缩首屏限制，不代替完整gaps。highlight须明确实际地域覆盖、部分周期和重要不可用渠道；未提供时首屏显示gaps前两条，执行智能体需确认关键限制未藏在后段。完整来源时间戳、检索方法和运行记录用原生details/summary保留，正文直接展示原始发布日期与原文链接。摘要和图表只表达本期合格样本，不能把默认江西全省与本期四地有限采集混为一谈。阅读视角不代表地域范围。部分周期除观察稿外必须在首屏标“部分周报/部分月报”等，并在gaps解释周期未完结，不能仅靠折叠运行记录提醒。

默认生成本地HTML及JSON。用户要求PNG长图时调用独立scripts/export_png.py，需Playwright和可用本地浏览器；基础HTML无此依赖。长图含真实中文摘要、图表、全部可见事实与专题，1080像素默认宽度，高度自适应，不自动发布。HTML/PNG输出已存在均拒绝覆盖。无Python可按契约人工编制并注明未运行辅助工具；导出依赖缺失时明确失败，不交付纯色图片、装饰数字、SVG改扩展名或空功能。
