# 周期分析与阅读对象适配

## 聚合顺序

先取发布日落在本期的已核验证据，核对有效配置，再做事件去重、主体归并、主题聚类。周月报不得从过去成品的概述直接再造证据；只有HTML、缺少原文/日期/出处的历史材料需要重建证据，不能假称已核实。max_items只截断展示卡片，分析基于全量合格底层证据；引用未展示卡片的事实时应扩展最终证据列表，展示总量上限须在配置摘要说明为“摘要卡片上限”，不可删证据来硬守卡片数。

## 三类信号

| 信号 | 可复算条件 | 不能算的情况 |
|---|---|---|
| 主题持续 | 同主题在本期≥3个不同发布日有不同实质事件/进展，列日期及ID | 同一旧稿跨日转载、同一天3篇报道 |
| 跨日新进展 | 同一主线在≥2个连续自然日各有新事实，列进展关系 | 同一公告两天转载、只改标题或抓取日 |
| 多源独立印证 | 同一事实有≥3个独立原始来源根，本期记录来源根与依据 | 省市媒体转载同一通稿、多网站同一附件 |

信号阈值仅是本技能的编辑规则，不是统计检验、风险评级或事实真实性保证。某条事实单一权威来源已核实时可以进稿，但不贴“多源”标记。同一主题不同事实的热度与同一事实的独立印证不能互换。无法证明独立性时不要打多源标签；可以写“获得多渠道关注”，但明确转载属性且不升高事实置信。

周报呈现：简洁报头与实际覆盖 → 顶部来源及主题图 → 真实内容提炼的一句话速览 → 政府/企业一级分区和部门/产业二级分类 → 周期变化及研究含义 → 后续核实清单 → 完整证据。分组可随配置删减空项，不强凑十节。速览写具体事项、变化和状态，不写条数目录；按摘要text及其evidence_ids逐句核对。图表直接由最终证据计算，不在HTML外临时拼接。

## 月报专题

优先选跨周持续、已核实政策拐点、项目里程碑、企业实质进展的主题。默认2–3个；只有1个充分就做1个。没有可论证专题时只给月度事实回顾和缺口，标观察稿，不将线索写成结论。

每题依次写：
1. 由头：本月已核实事件与ID；必要旧背景单列“背景”，不得计入当月新事实数。
2. 机制：政策如何作用到产业或企业活动，注明为分析推断。
3. 对比：只有同口径、同期数据才比较；不可比则说明限制，不补编数据。
4. 三视角：政策目标、企业响应、经营管理可关注事项。
5. 证据表：每个论断对应事实ID、原始来源、统计口径、反证及局限。
6. 条件化判断：“如某里程碑由正式公告确认，可进一步研究某服务场景”，不得写确定融资需求或审批结论。
7. 下期关注：具体需要核实的公开事项、预计披露窗口（有依据才写），不自动改配置或发送提醒。

## 阅读视角目录

阅读视角是可选配置，不是页眉。所有视角共用同一证据门和筛选结果；只调整首屏排序、展开深度和跟踪问题。没有明确选择时使用全省阅读。页面不展示部门、岗位或内部机构名称。

共同首屏：先看本期政府/企业原始披露主体与实质主题，再看提炼的内容摘要。主题按产业方向、科技攻关、数智化、企业资金安排等内容归并，每条一个主theme；阶段另存stage，不把审批手续本身当成所有事项的产业主题。日期留在事实卡，不做发布日计数图。图形按数据关系选择，不能强制所有报告同一套图；不同项目的阶段分布不串成漏斗或连续进度。

| 视角键 | 可读名称 | 优先展开 | 明确不展示 |
|---|---|---|---|
| province | 全省阅读 | 跨区域差异、产业链、规则共性 | 内部排名、客户归属、额度 |
| regional | 区域机构 | 辖内政策、项目阶段、重点企业进展 | 未核实营销安排 |
| executive | 行领导 | 跨区域重大项目、政策变化、例外事项 | 流水账、内部考核 |
| corporate | 公司金融 | 产业项目、重点企业公开进展、产业链关系 | 贷款需求推断 |
| strategic_clients | 战略客户 | 已核验重点企业、集团及重大项目主体 | 未核验子公司并表 |
| tech_finance | 科技金融 | 技术攻关、数智化采购、研发与中试 | 把采购启动写成建设完成 |
| inclusive | 普惠金融 | 园区平台、中小制造、专精特新公开线索 | 企业规模或授信资格推断 |
| institutions | 金融机构 | 政府平台、基金备案、公开金融同业 | 同业内部份额 |
| transaction_banking | 交易银行 | 结算、现金管理、供应链公开安排 | 账户或交易流水 |
| bills | 票据业务 | 公开票据、付款与供应链安排 | 未披露票据余额 |
| cross_border | 跨境金融 | 跨境投资、基金、进出口与海外主体 | 未披露跨境额度 |
| retail | 零售金融 | 与区域消费、就业直接相关的公开事项 | 个人客户信息 |
| retail_credit | 零售信贷 | 个人端不默认展开；仅保留公开规则 | 个人授信线索 |
| private_banking | 私人银行 | 不从企业新闻推断个人客户 | 个人资产或联系方式 |
| wealth | 财富管理 | 区域产业与企业基本面，供研究参阅 | 产品推荐、收益承诺 |
| planning_finance | 计划财务 | 已披露预算、投资、募集资金口径 | 不同口径金额相加 |
| risk | 风险管理 | 审批阶段、废标、冲突数据和覆盖缺口 | 未评级企业的风险等级 |
| credit_approval | 授信审批 | 主体、项目阶段、金额口径、反证 | 审批结论或额度建议 |
| operations | 其他中后台 | 覆盖完整性、来源冲突、待复核项 | 业务机会排序 |
| relationship | 一线客户经理 | 可公开跟踪的主体、阶段和下一步公开文件 | 电话、拜访和内部归属 |

目录可继续追加，但新增视角必须说明优先展开和禁止展示，不能只增加一个名称。私人银行、零售信贷、财富管理默认少展开，避免把政企新闻误写成个人业务线索。风险管理、授信审批和计划财务优先看口径、阶段和反证。业务部门优先看主题，不优先看发布时间。

## 排序与数量

先按用户关注匹配解释，再按事实的可核实影响、政策期限/项目里程碑、时效性作编辑排序。输出“编辑优先级”而非虚构量化评分；若提供计分，必须公开维度/分值/每条依据并可复算。企业负面和正面均按相同证据门，不默认偏向任何主体。条目不足可少出，不将未核验内容补位。
